# 검색 tool과 에이전트 검증

## 실행 구조

`chatbot.py`는 LangChain `create_agent`와 ChatOpenAI로 단일 에이전트를 만든다. 모델은 `.env`의 `OPENAI_CHAT_MODEL`이며 기본값은 `gpt-5-mini`다. 임베딩 모델은 기존 `text-embedding-3-small`을 유지한다.

질문 → `before_agent`의 Gemini 입력 검사 → 에이전트의 tool 선택 → `tools.py`의 `search_personal_documents(query)` → 기존 `retriever.py`의 Chroma 검색 객체 → 상위 5개 청크 본문·문서 ID·제목·출처 경로 → 에이전트 최종 답변의 흐름이다. tool은 DB를 읽기만 하며 적재를 실행하지 않는다.

## 입력 욕설·비방 가드레일

`guardrails.py`는 Google GenAI SDK의 `gemini-3.5-flash-lite`를 judge로 사용한다. 키와 모델은 `.env`의 `GEMINI_API_KEY`, `GEMINI_GUARDRAIL_MODEL`로 설정한다. 판별 프롬프트는 `prompts/guardrail.txt`에 분리했다. 본 에이전트용 프롬프트와 원문 자료는 Gemini에 보내지 않고 최신 사용자 입력만 보낸다.

`before_agent(can_jump_to=["end"])`는 한 번의 invoke에서 한 번 실행된다. Gemini는 JSON 스키마에 맞춰 `profanity`, `harassment`를 반환하며, 둘 중 하나라도 true면 고정 문구 '욕설이나 비방이 포함된 메시지는 에이전트에게 전달되지 않습니다.'를 AIMessage로 추가하고 `jump_to="end"`를 반환한다. 욕설을 포함한 질문 전체를 차단하며 정제 후 전달하지 않는다. 금칙어 목록으로 판정하지 않는다.

정상 입력은 상태를 변경하지 않고 기존 에이전트로 이어진다. tool 실행 후 LLM이 다시 호출되어도 Gemini 판별을 반복하지 않는다. 판별 실패·잘못된 JSON·키 누락 시에는 정상 입력으로 간주하지 않으며, '입력 검사 서비스를 이용할 수 없습니다. 잠시 후 다시 시도해 주세요.'를 반환하고 종료한다. 이는 욕설 판정과 구분한다.

`test/test_guardrails.py`의 로컬 테스트는 차단 시 모델·retriever 미호출, 정상 입력의 tool 루프에서 judge 1회 호출, 판별 오류 종료, 엄격한 응답 검증, 최신 사용자 입력 선택을 검사한다. 실제 판별 테스트는 욕설·초성·기호 변형·비방·판별 지시 우회와 정상 질문·불만·정상 유사 단어를 포함한 10개 입력을 사용한다. Gemini는 실제 호출하고 본 모델은 호출 횟수를 계측하는 대역을 사용해 라우팅을 확인한다. 별도로 정상 개인 질문 1개는 실제 Gemini → GPT → 검색 tool → 답변까지 실행한다. 결과는 `test/reports/guardrails.json`에 저장한다.

이 테스트는 준비한 사례에 대한 검사이며 한국어의 모든 변형·문맥에서 오탐·미탐이 없음을 보증하지 않는다.

## 최종 답변의 개인정보 마스킹

`guardrails.py`의 `mask_private_output`은 `after_agent` 노드 스타일 훅이다. 마지막 AIMessage의 본문만 정규표현식으로 검사하고, 같은 메시지 ID로 치환해 최종 답변이 원문과 함께 중복으로 반환되지 않게 한다. 추가 LLM 호출은 없다.

- 국내 휴대전화 번호는 앞 3자리와 마지막 2자리만 유지한다. 예: `010-1234-5657` → `010-xxxx-xx57`. 하이픈·공백·점 구분과 붙여쓰기를 처리한다.
- 숫자 건물 동·호수는 `xxx동 xxx호`로 바꾼다. 예: `서울시 송파구 동남로 193 105동 1804호` → `서울시 송파구 동남로 193 xxx동 xxx호`. 동·호수가 따로 쓰이거나 Markdown 강조로 감싼 경우도 처리한다.
- 실제 치환이 있었을 때만 `개인정보는 가려질 수 있습니다.`를 한 번 붙인다. 이미 가린 내용이나 개인정보가 없는 답변에는 새 안내문을 붙이지 않는다.
- 이 처리는 현재 완성된 최종 답변의 텍스트에 적용한다. 원본 문서·DB·검색 tool 메시지를 변경하지 않는다. 모든 주소 표현이나 국제 전화번호를 처리하는 범용 개인정보 탐지기는 아니다.

`test/test_guardrails.py --offline`은 전화번호·주소 표현, 도로명·193 유지, 안내문 중복 방지, 메시지 교체와 에이전트 그래프 적용을 검사한다. 기본 실행은 실제 Gemini·GPT·검색을 사용하는 전화번호·거주지 질문도 추가로 실행하며, 보고서에는 해당 최종 마스킹 답변과 검사 결과만 기록한다.

개인 이력·경험·프로젝트 수치는 검색 후 답하도록 시스템 프롬프트에 명시한다. 인사나 일반 개념 설명에는 tool 호출을 요구하지 않는다. `tool_choice=required`나 키워드 라우터로 강제하지 않고 모델이 tool을 선택한다. 검색 실패는 근거 없음으로 변환하지 않고 오류로 처리한다.

검색 자료는 내부 사실 확인에 사용하고 최종 답변에는 출처·근거 표기나 문서 경로를 붙이지 않는다. 팀 기능·개인 기여, 계획·완료를 구분하고, 검색 결과에 없는 정보는 확인할 수 없다고 답하도록 지시한다. 프롬프트 지시만으로 모든 질문의 도구 사용과 사실성을 보장하지는 않는다.

`jonghwa-agent` CLI는 프로세스와 에이전트를 유지하면서 질문 입력을 반복한다. `/exit`, `/quit`, Ctrl+C 또는 EOF로 종료한다. `invoke_agent`는 매번 새 메시지 목록으로 호출하므로 현재 각 질문은 독립적으로 처리하며 세션 기억은 사용하지 않는다. 반환된 전체 메시지에는 모델의 tool 요청·실행 결과·최종 답변이 포함된다.

## 테스트

`test/test_agent.py`는 로컬 tool 단위 테스트 3개와 실제 모델·DB를 사용하는 질문 10개를 실행한다. `--offline`은 단위 테스트만 실행한다.

| 질문 분류 | 개수 | 검사 |
| --- | --- | --- |
| 개인 사실 | 8 | 실제 tool 호출과 응답 메시지, 예상 문서 검색, 핵심 사실 문자열, 출처 표기 미노출 |
| 문서에 없는 월 매출 | 1 | 검색을 실행하고 확인할 수 없다고 답하는지 |
| 일반 인사·산수 | 1 | 검색 없이 답하는지 |

학력·인턴 업무·Pick!ture의 CLIP 점수·Embodied AI 입력 설정·ICT_CUBE 역할·ARZONE 인증·탐라로그 지도 오류와 오디오 저장을 질문한다. 모델에는 질문과 시스템 프롬프트, tool 정의만 전달하고 예상 문서 ID·정답 표현은 전달하지 않는다. 검색어도 모델이 작성하며 DB 전체에서 검색한다.

개인 질문은 각 핵심 사실 그룹의 대체 표현 중 하나 이상이 답변에 있어야 한다. 모델의 tool call ID와 ToolMessage ID를 비교하고, 답변에 출처 표기와 검색 문서 경로가 노출되지 않는지 검사한다. 답변에 특정 출처 문자열이 있어야 한다는 조건은 사용하지 않는다. ICT_CUBE의 개인 역할 답변에 탐라로그의 문화·협동·보물 미션을 섞는 알려진 오류도 금지 표현으로 검사한다. 모든 질문을 통과해야 성공 종료한다. 중간 API 오류는 해당 질문을 실패 처리하며 보고서에 오류 타입을 기록한다.

`test/reports/agent.json`에는 질문별 검사 결과, tool 검색어·결과 청크, 최종 답변과 메시지 전체를 저장한다. 개인 자료가 포함되어 Git에서 제외된다. 이 테스트는 도구 실행·핵심 사실·출처 표기 미노출의 회귀 검사이며, 단어 포함 여부만으로 답변의 모든 주장과 추론이 정확하다고 판정하지 않는다. 실제 답변과 도구 본문을 함께 검토해야 한다.
