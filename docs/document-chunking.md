# 프로필 원본 문서 형식과 청킹 기준

## 적용 범위

`data/documents/profile/profile.md`는 CV를 한국어로 정리한 RAG 입력용 초안이다. 원본 CV는 수정하거나 복사하지 않았다. 이름, 생년월일, 연락처, 개인 링크는 사용자가 직접 입력하도록 비워두었다. 그 외 사실은 CV 1쪽에서 확인되는 범위만 작성했다.

문서 분할 방식은 LangChain의 [MarkdownHeaderTextSplitter 공식 가이드](https://docs.langchain.com/oss/python/integrations/splitters/markdown_header_metadata_splitter)를 참고했다. 공식 가이드는 제목별 분할, 제목 메타데이터 보존, 긴 섹션에 대한 추가 분할을 지원한다. 아래 프로필 형식과 수치는 이 프로젝트의 초기 설계이며 보편적인 표준이나 최적값을 의미하지 않는다. 현재 청킹·인덱싱 코드는 미구현이다.

## 원본 작성 규칙

- UTF-8 Markdown으로 작성한다.
- `#`는 문서 제목, `##`는 정보 범주, `###`는 개별 경력·프로젝트·수상 등 하나의 주제에 사용한다.
- 한 섹션에는 하나의 주제를 담는다. 프로젝트의 역할·기술·성과를 작성할 때는 같은 프로젝트 제목 아래에 둔다.
- 문장은 개별 청크만 읽어도 대상을 알 수 있도록 회사명·프로젝트명 등을 명시한다. 표, 이미지, '위 프로젝트' 같은 문맥 의존 표현을 피한다.
- 원문에 없는 수치·역할·기술 스택은 추가하지 않는다. 한국어로 옮긴 프로젝트 설명은 원문 제목과 구분한다.
- 날짜는 확인된 정밀도로만 적는다. 졸업 예정과 완료, CV의 '현재'와 실제 현재 상태를 구분한다.
- 근거가 있는 섹션마다 원본 파일명과 쪽수를 남긴다. 추후 별도 프로젝트 문서가 생기면 개요만 프로필에 유지하고 상세는 해당 문서에서 관리한다.
- 기본 정보와 연락처의 빈 값은 미입력 상태다. '없음' 또는 실제 사실로 해석하지 않는다.

## 문서 메타데이터

YAML front matter는 본문과 분리해서 읽고 임베딩 대상에서 제외한다. `MarkdownHeaderTextSplitter`만으로 front matter를 자동 처리한다고 가정하지 않는다.

| 필드 | 의미 |
| --- | --- |
| `document_id` | 파일명이나 내용이 바뀌어도 유지할 논리적인 문서 ID |
| `document_type` | 문서 유형. 현재는 `profile` |
| `language` | 본문 언어 |
| `status` | 초안 여부. 현재는 `draft`, 사용자 검토 후 `ready`로 전환 |
| `visibility` | 공개 범위. 현재는 `private` |
| `updated_at` | 이 Markdown을 작성·수정한 날짜. CV 작성일이나 사실의 유효일이 아님 |
| `source_file`, `source_pages` | 참조한 원본 파일과 쪽수 |
| `source_date` | 원본의 작성 기준일. CV에 명시되어 있지 않아 `null` |

개인정보를 채운 뒤에도 공개 범위는 별도로 검토한다. `visibility`는 문서 전체에 적용하므로 공개 프로필이 필요하면 공개 가능한 내용만 별도 문서로 분리한다. 공개 검색은 `ready`이며 공개가 허용된 문서만 대상으로 설계한다. 메타데이터 작성만으로 실제 접근 제어가 구현되는 것은 아니다.

## 청킹 순서

1. Front matter를 분리하고 문서 메타데이터를 읽는다.
2. 빈 값만 있는 기본 정보·연락처 섹션은 제외한다. 일부 값을 채웠다면 값이 없는 항목만 제외하고 나머지는 유지한다.
3. `MarkdownHeaderTextSplitter`로 `#`, `##`, `###` 경계에서 분할한다. `return_each_line`은 사용하지 않고 같은 주제를 묶는다.
4. 제목을 메타데이터에 저장한다. 임베딩 텍스트에도 전체 제목 경로를 한 번 붙여 '경력 / 회사명', '연구 및 프로젝트 / 프로젝트명' 문맥을 유지한다.
5. 짧은 경력·프로젝트 섹션은 그대로 한 청크로 유지한다. 긴 섹션만 `RecursiveCharacterTextSplitter.split_documents()`로 추가 분할한다.
6. 추가 분할의 초기값은 `chunk_size=1000`, `chunk_overlap=150` 문자로 둔다. 이는 토큰 수가 아니다. 문단·줄·문장 경계를 우선하고, 서로 다른 프로젝트나 섹션 사이에는 overlap을 적용하지 않는다.
7. 각 하위 청크에 원본 메타데이터, 제목 경로, 출처 쪽수, 하위 순번을 유지한다. 출처 줄이 떨어져 나가도 출처를 추적할 수 있어야 한다.

청크 ID는 문서 ID, 제목 경로, 섹션 내 순번으로 만들 수 있다. 재등록 시 해당 문서의 이전 청크를 교체해 삭제·축약된 부분의 오래된 청크가 남지 않게 한다.

## 초기 확인 질문

- 학교, 전공, 학점, 졸업 예정 시기를 올바른 학력 섹션에서 찾는가?
- Hyper-AI의 개인 담당 업무와 다른 프로젝트 목록을 혼동하지 않는가?
- 특정 프로젝트의 기술 스택이나 성능 수치를 물으면 자료 부족을 인식하는가?
- 인턴 재직 여부를 물으면 CV의 진행 중 표기를 현재 사실로 단정하지 않는가?
- 생일·이름·연락처를 입력하기 전에는 빈 값을 검색 근거로 사용하지 않는가?

실제 임베딩 모델을 선택한 뒤 이 질문들로 검색 결과를 확인하고 청크 길이와 overlap을 조정한다.
